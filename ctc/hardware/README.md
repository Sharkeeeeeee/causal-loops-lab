## 一個電路，三種規則

每個電路最多 6 個量子位元：

1. 隨機的 CR 輸入用 RY 準備，再用 CNOT 複製到一個記錄位元。這個記錄位元代表「已記錄的過去」；在量子擦除裡，它就是 Bob 的閒置光子。
2. 迴圈位元 m 和夥伴位元 p 一開始處於 Bell 態 |Φ⁺⟩。
3. 對 CR⊗m 作用 U。
4. 對 (m, p) 做 Bell 測量，結果 00 代表迴圈自洽地閉合。

| 規則 | 怎麼從資料算出來 |
|---|---|
| 無迴圈（未知的外部訊息） | 不看 Bell 測量結果。m 單獨看是最大混合態 |
| P-CTC | 只留 Bell 結果 00 的 shots |
| 過去守恆 | 每個世界的權重用全部 shots 算；世界之內只留 00 的 shots。沒有自洽歷史的世界退回 D-CTC，這些電路的 D-CTC 不動點都是最大混合態，所以等於不看 Bell 結果（`fallback_matches_no_loop` 用精確計算驗證過） |

## 實驗

| 實驗 | 故事 | 檢驗的定理 |
|---|---|---|
| `grandfather` | 收到訊息 m 就送回 NOT m；槍卡住（機率 0.2）時什麼都不做 | 定理 1(2)(3)、定理 2(1) |
| `refusal` | 收件者把訊息記進日誌；若 a = 1，寄件者拒絕寄出收到過的訊息 | 定理 1(1)、定理 2 |
| `one_way` | a 控制迴圈上的 NOT，迴圈從不作用在 a 上 | 定理 3 與 P-CTC 反例 |
| `eraser_x`、`eraser_y` | 雙縫的路徑跟 Bob 的閒置光子糾纏；來自未來的訊息在右縫加上 π/2 相位。Bob 用 X 讀（擦除），路徑用 X 和 Y 讀，合起來得到條紋 | 定理 0、PAST_PRESERVING.md 的雙縫結果 |
| `eraser_z` | 同上，但 Bob 用 Z 讀（which-path） | P-CTC 傳訊的直接示範 |

## 怎麼跑

需要 Python 3.11、`qiskit`。真實硬體還需要 `qiskit-ibm-runtime` 和一個 IBM Quantum 帳號（免費方案目前每月 10 分鐘 QPU 時間；第三次執行用了 83 秒）。

```text
python -B ctc/tests/test_hardware.py      # 電路、估計方法、讀取校正的檢查
python -B ctc/hardware/run_local.py       # 理想模擬器，跑完整分析流程
python -B ctc/hardware/preregister.py     # 送出前固定預測和判準
python -B ctc/hardware/run_ibm.py --dry-run
python -B ctc/hardware/run_ibm.py --backend ibm_kingston
```

存帳號（只需一次；程式不會要求或儲存你的 key）：

```python
from qiskit_ibm_runtime import QiskitRuntimeService
QiskitRuntimeService.save_account(channel='ibm_quantum_platform', token='<你的 API key>', set_as_default=True)
```

`run_ibm.py` 的流程：

1. **Preflight：** 用幾秒鐘實測全部量子位元的讀取錯誤（裝置公布的校正資料不一定可靠，見下面第一、二次執行）。
2. **選佈局：** 排除實測讀取錯誤超過 3% 的量子位元，用 VF2 列舉每個電路在耦合圖上的所有放法，選讀取錯誤加雙量子位元閘錯誤最小的。電路不需要任何 SWAP。
3. **主 job：** 所有實驗加上每組量子位元的讀取校正電路，開啟 dynamical decoupling（XpXm）和閘、測量的 Pauli twirling。
4. **分析：** 讀取校正後，用 bootstrap（同時重抽實驗 shots 和校正資料）估計標準差，最後逐項評估預先登錄的判準。

## 注意事項

- **讀取校正的影響不小。** 第三次執行裡，量子位元 147（祖父悖論、單向控制、量子擦除的 CR 位元）在 preflight 實測讀取錯誤 0.46%，幾分鐘後在主 job 的校正電路裡變成約 8%。原因不明，可能是漂移，也可能跟測量 twirling 有關。同一個 job 裡的校正抓到了它，校正矩陣條件良好（1 − e₀ − e₁ ≈ 0.83），標準差也包含了校正的不確定度。但未校正的數字明顯較差，例如祖父悖論的過去守恆值未校正時是 0.263，用未校正數字的話這一項 C2 不會通過。
- **量子擦除的清晰度剛好過門檻：** 0.870，門檻 0.85。無迴圈的清晰度也同樣下降（0.645 對 0.707），兩者比例都約 0.92，符合一般的去相干，而不是規則本身的偏差。
- **登錄檔沒有外部時間戳記。** 結果檔記錄的取回時間是 2026-11-22T18:18:36Z，`PREREGISTRATION.md` 和結果是在同一個 commit（2026-11-22T18:26:27Z）加進 git 的。結果檔裡的 SHA-256 由 `run_ibm.py` 自己寫入，只能證明存結果時登錄檔的內容，不能由第三方證明它在送出 job 之前就存在。下一次執行應該先把登錄檔推送到 GitHub 或有時間戳記的存放處，再送出 job（[PERSPECTIVES.md](../../PERSPECTIVES.md) 2.2）。
- **不是第一個在可程式量子電腦上的 P-CTC 實驗。** 2025 年有一篇在 IBM 和 Quantinuum 處理器上的實驗（arXiv:2501.16335，見 [LITERATURE_REVIEW.md](../../LITERATURE_REVIEW.md)）；Lloyd 等人 2011 和 Ringbauer 等人 2014 是光學實驗。
- **判準是在前兩次執行之後才定的。** 門檻因此參考了前兩次的雜訊大小；量子擦除電路則是第一次跑。
- **「應該是 0」的量受雙量子位元閘錯誤限制。** 拒絕寄件的不自洽歷史從 0.112（13 個雙量子位元閘）降到 0.035（7 個），讀取校正修不掉這部分。
